# 领域燃料：把通用能力延伸到真实业务

CodingKeeper 有 **44 类通用燃料 + 17 个领域包、85 类领域燃料**，共 129 个内置改进方向。方向称为「改进燃料」，每轮可验收的成果称为「改进工单」。领域包可以组合，不要求把项目归到唯一行业。

## 当前领域目录

| 包 ID | 适用的已有能力 | 五类改进方向 |
|---|---|---|
| `ai-agents` | 模型调用、Agent、工具执行、上下文管理 | 任务评测；工具边界；上下文与记忆；预算与降级；轨迹重放 |
| `retrieval` | 文档摄入、检索、知识库、带来源的研究 | 解析完整性；相关性；引用支撑；知识权限；更新与删除 |
| `saas` | 账户、工作空间、角色、邀请、套餐 | 租户隔离；角色一致性；邀请加入；许可兑现；操作历史 |
| `commerce` | 订单、支付、订阅、库存、购买授权 | 订单状态；支付幂等与对账；退款生命周期；库存一致性；购买后交付 |
| `finance` | 金额、账目、市场数据、财务分析、回测 | 金额精度；账目对账；市场时间；回测偏差；结论依据 |
| `content` | 素材、草稿、编辑、审核、发布 | 草稿恢复；来源事实；发布回执；渠道格式；效果回流 |
| `realtime` | 聊天、通话、实时连接、房间、在线协作 | 顺序交付；重连恢复；会话生命周期；在线隐私；通知意图 |
| `data-platform` | 采集、清洗、同步、ETL、统计、报表 | 数据契约；来源新鲜度；补采重放；数据质量；增量一致性 |
| `native-apps` | Android、iOS、桌面应用 | 生命周期权限；离线同步；设备资源；升级恢复；设备输入兼容 |
| `developer-tools` | CLI、API、SDK、开发环境、适配器、插件 | 协议版本；项目隔离；脚本契约；扩展兼容；可复现环境 |
| `discovery` | 候选目录、排序、推荐、发现 | 排序质量；冷启动覆盖；推荐依据；目录健康；反馈与滥用 |
| `automation` | 触发器、定时任务、执行队列、多步工作流 | 触发时刻；动作幂等；失败补偿；执行身份；审计重放 |
| `identity` | 设备指纹、身份识别、风险信号、挑战验证 | 稳定误差；数据最小化；风险依据；挑战恢复；SDK 权限 |
| `search-growth` | 公开页面、SEO/GEO 产品、搜索效果评测 | 可索引性；真实结构化数据；内容覆盖；来源权威；效果核对 |
| `media` | 音视频、图像、媒体生成、播放、处理、导出 | 格式契约；时间轴同步；素材生命周期；播放恢复；来源与质量 |
| `learning` | 课程、测验、技能练习、学习内容 | 进度证据；测验反馈；练习复盘；先修关系；学习者控制 |
| `browser-extensions` | 浏览器扩展、内容脚本、后台、浏览器 API | 站点权限；消息边界；后台休眠；存储同步；清单兼容 |

每个包只在实际能力存在时适用。例如启用金融包不意味着必须新增回测；有金额计算可以检查精度，没有回测则该方向不适用。全套详细指令及稳定 ID 用 `ck prompts packs <包ID>` 和 `ck prompts show <方向ID>` 查看。

## 项目怎样匹配

先读项目约定、README、源码入口、API、数据格式、测试和待办，再建立「已有能力 → 包 → 证据 → 可验收结果」的关系。项目名称、目录名和技术栈不能独立证明业务能力。

以下建议依据 2026-11-12 读取到的实际根目录 README，供相应项目 Agent 进一步核对源码。它们是选择建议，未批量改写这些项目的状态：

| 项目 | 已声明能力 | 建议组合 |
|---|---|---|
| CodingKeeper / codexc | 编码工具控制器、CLI、任务队列、进程监管、验收与自动调度 | `developer-tools` + `automation` |
| soul2soul | Android 配对与通话、屏幕共享、双向音频、标注 | `realtime` + `native-apps`，已有媒体链可加 `media` |
| fingerprint | 设备指纹与风控、租户账户绑定、多平台 SDK | `identity` + `developer-tools`，团队能力可再核对 `saas` |
| airesearch | 搜索、阅读、来源评分、综合引用、SQLite 状态、缓存、续跑、导出 | `retrieval` + `ai-agents`，数据链可加 `data-platform` |
| sale | 课程、测验、AI 技能练习、录制与复盘，指定 sale.txt 为权威内容源 | `learning` + `content`，录制链可加 `media`；不能按名字当电商 |
| wechatflow | 内容 AI 员工、个人资料与规则、草稿工作流 | `content`；缺个人材料、个人故事及转化选择留人类决定 |
| producthunter | Agent 搜索、相关性与热度排序、候选发现 | `retrieval` + `discovery` |
| agentos | Agent 协作 API、OKR 拆解、任务调度、token/成本分析、CLI | `ai-agents` + `automation` + `developer-tools` |
| AIGEO | SEO/GEO 诊断监测、schema 建议、CLI/API | `search-growth` + `developer-tools` |
| all-api-hub | 浏览器扩展、账户余额/用量/价格、凭证、签到、模型同步 | `browser-extensions` + `developer-tools`；金额路径可单独核对金融方向 |
| aitv | Android TV/手机语音陪伴、Live2D、ASR/对话/TTS、家长 PIN/时间/麦克风控制 | `native-apps` + `media` + `ai-agents`；学习方向需实际训练目标支持 |

## 从一个方向产生多张真实工单

方向数量不会限制可发现的问题数量。领域燃料沿实际能力、用户状态和失败模式继续展开：

- 检索引用：原文位置错误、表格事实丢失、版本过期、来源冲突、已删文档残留、撤权后缓存泄露，可分别产生不同根因的工单。
- 实时协作：重连、乱序、确认丢失、双方结束状态、前后台切换、多设备通知，每项都以已有协议和设备范围为依据。
- 学习培训：评分与教材不符、进度恢复错误、练习反馈无依据、录音断链、先修导航错误，各自对应可核对的学习流程。
- 浏览器扩展：后台休眠丢状态、标签页消息串用、撤权后仍访问、同步覆盖、清单兼容，分别以本地假 API 和实际浏览器验收。

交叉检查用「已有能力 × 用户状态 × 数据/时间边界 × 失败模式 × 支持平台」。先去重、确认价值、查已有实现与证据，再选择最值得完成的一项。同一根因跨多个分支应一次修复，不能为了多烧回合拆成重复任务。

## 如何继续增加领域

当前可以继续研究的候选有地理空间、物联网与设备控制、医疗信息工具、科学计算、设计创作工具、游戏，以及招聘/CRM。先发现真实项目和已交付能力，再决定是否沉淀成包；这些候选尚未加入活动目录。

例如地理空间的坐标系、距离单位、空间索引、地图层级和位置隐私，或物联网的设备绑定、断线重连、命令确认、固件兼容和遥测质量，都可能成为细分领域通用能力。涉及医疗、物理设备、真实交易或个人敏感信息时，需要以现有授权和本地模拟为边界；实现测试不能冒充临床、实机或业务效果验证。

一个新领域包应提供：

1. 稳定包 ID、清晰适用条件及不适用条件。
2. 已有项目的能力证据和独立于技术栈的用户目标。
3. 五个互补的初始方向，每个都有唯一 ID、具体失败样例、可交付结果和能判失败的验收。
4. 数据/来源要求、授权边界及需要人类选择的点。
5. 与现有通用/领域方向的区别，以及配置、轮转、兼容和容量的回归。

内置定义在 `ck-fuel-packs.py`。只有一个项目适用的特殊方向先放 `.codingkeeper/prompts/*.md`，使用 `ck prompts add <ID> --file <文件>`；出现跨项目共同契约后再升级为领域包。

## 夜间执行和晨间接手

```bash
ck prompts packs
ck prompts enable retrieval ai-agents
ck prompts list
ck propose --file ./decision.md
ck morning
```

Agent 自主完成已授权、可逆、可验证的工作；把证据充分的产品选择写成稳定 `DECISION-*` 工单。某个方向待人决策时，继续独立方向。没有真实差距就记录 idle，完整两遍无产出后在线等待，默认每小时复查。新队列、源码或活动目录变化可重新开放扫描。详情见 [FUEL.md](FUEL.md)。

本轮为 CodingKeeper 本仓库启用开发工具和自动化包；其他项目由各自 Agent 核对后启用。旧 runner 的环境筛选及旧部署副本仍需检查，不能根据目录变多就认定全部项目已连续运行一整夜。
