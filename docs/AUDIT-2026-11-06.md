## 已复现并修复的问题

| 问题 | 根因及影响 | 修复与回归 |
|---|---|---|
| 全天模式无法复燃 | watchdog 拒绝窗口 helper 的 disabled/零截止时间结果 | 接受明确的无限制结果，坏响应仍阻断；watch-window |
| 复燃突破显式时段 | revive 硬编码空窗口及上海时区 | 原样传递用户时段/时区；watch-window |
| 阶段成功后残留后台进程 | worker/gate 只等待直接子进程，后台进程可以继续改代码 | 三阶段共享受管进程组，完成后清理组成员再验收；burn-runtime |
| runner 强制终止后 worker 继续执行 | SIGKILL 无法触发 EXIT 清理 | 独立监护进程核对 owner 出生标识，owner 消失后停止本组；burn-runtime |
| 等待事务锁时误验收 | 候选只在等待锁之前校验 | 获得 acceptance.lock 后再次校验候选；burn-runtime |
| 示例及验收标题解析错误 | 代码围栏只记前三个字符，缩进标题被误当分区 | 区分围栏长度与真正二级分区，保留缩进合同；burn-runtime |
| 队列数量失真 | 状态/横幅/fuel 各自用 grep 或独立简化解析器 | 共享 queue_items/queue_stats，示例与 review-needed 不计 ready；burn-runtime |
| 缺少门禁仍启动模型 | 非 ZCode 自动入口默认允许跳过 gate | 自动 run 默认要求真实 gate/Git，官方占位阻断；显式 legacy 例外可追溯；burn-runtime |
| 新加任务后提前耗尽 | 验收队列任务未清空之前的 idle_count | 完整验收后重置空转预算；burn-runtime |
| 审查日志中的旧零结论误放行 | parse_bugs 取最后含 BUGS 的行，而非最终行；默认审查混读 CLI 日志 | 使用 --output-last-message，日志另存，最终非空行必须是正式 BUGS 结论；burn-runtime |
| 新入队遮蔽旧格式队列 | 未迁移 .codexc 时，新 queue 会优先于旧任务 | 发现旧队列时拒绝直接新建，保留原任务；prompts |
| 自测失败仍返回成功 | 多个断言只打印 FAIL | 每个失败断言累加失败数并非零退出；故障注入自测验证；burn-runtime |

每类修复都有旧实现失败的最小复现。watch-window 沿用并加强了原失败回归；新运行回归能通过 `CK_AUDIT_SOURCE` 指向保存的旧源码重现。自测断言已改为调用真实 parse_bugs，避免测试复制旧解析逻辑。

## 工程燃料与持续加料

新增 `ck-prompts.py`，内置 correctness、reliability、security、edge-cases、test-coverage、performance、observability、dependencies、maintainability、documentation 十类指令。每类限定真实缺口、复现、小步修复和验证，避免仅为消耗配额制造任务。

`ck prompts list/show/add` 管理内置及 `.codingkeeper/prompts/*.md` 项目指令；新增文件完整写入后原子发布，拒绝覆盖已有项目指令。`burn-cursor.json` 保存轮换位置。新 Prompt 可在运行期间加入，默认每两遍完整燃料库没有源文件变化后进入非活跃 waiting_fuel，保持在线且不发送模型请求。新 ready 任务、或项目 Prompt 新增/修改会自动恢复；队列任务始终优先。人工 loop.halt 不会被加料清除。

`ck enqueue` 接受文字、`--file` 或 `--prompt`，与验收共享锁，多行验收合同逐字保留；不把文本当 shell 执行，不丢并发添加任务，未完成验收事务会明确阻止改写队列。headless evidence 保存 worker Prompt、输出和 burn 目标；审查收到具体燃料目标。CLI 与桌面识别 waiting_fuel，不把等待算成模型执行。

`zcodec run` 默认全天与 burn 开启。显式 `CODEXC_LOOP_IDLE=0` 等待队列；显式时间窗仍约束 headless worker/gate/review 和 watchdog。自定义 CODEXC_LOOP_IDLE 文本或 CODEXC_PROMPT_ROTATION=0 保留原单指令及空转停炉语义。

## 兼容与后续边界

- 未请求真实 Codex/ZCode/Claude/Pi/OpenCode/dsh 服务；离线通过证明管控状态机与适配协议，不能证明当前凭证、提供商或每个 CLI 新版本的真实可用性。
- 自动入口默认需要 Git 根目录与真实门禁。非 ZCode 显式 CODEXC_REQUIRE_GATE=0 可运行历史非 Git/无 gate 用法；它缺少源代码绑定和真实测试证据，不等于工程验收。
- 进程组清理管理同组成员；主动 setsid 的守护进程、外部 GUI 服务需要由工具/项目自身管理。ZCode plan/restrictions 仍不是操作系统沙箱。
- 未配置运行窗口时，配额错误无法可靠推测重置时间，会停炉等待恢复；凭证失败和真实 BLOCKED 保留人工暂停。持续运行不等于绕过上游配额或业务依赖。
- watchdog 仍是本机四个固定 ZCode 项目的运维脚本，通用注册表与跨工具启动参数持久化尚需产品化；evidence/blob 历史也尚无自动保留策略。
- 本轮未启动其他业务仓库的模型任务，未推送远端。已安装桌面二进制未覆盖；源码和编译回归已验证，新 waiting_fuel 展示在重新安装/启动新版面板后生效。
