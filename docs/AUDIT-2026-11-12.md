## 发现与处理

| 问题 | 影响与修复 | 回归证据 |
|---|---|---|
| 无证据 idle 回合使用 `git reset --hard` | 会丢掉用户原有暂存/未暂存改动及 worker 提交；改为保留所有代码、提交与证据，停炉等待核对，不验收 | `burn-runtime` 的脏树与首次提交前用例：旧代码分别将用户内容变回 `base`、继续第二轮；修复后两项通过，并核对暂存内容、未跟踪文件、HEAD 与无验收记录 |
| 大文件只存哈希的修复没有覆盖预算和 diff | 128 MiB 预算未计入即将写入的文件；小文件因预算耗尽没有 blob 时 diff 读取失败；blob 元数据误参与源码身份 | `leaf-runtime` 覆盖满预算、哈希文件 diff 和验收；预算使用 prospective size，源码身份与证据存储方式分离 |
| 看门狗提前删除审核/配额 halt | 时段关闭、runner 仍活或复燃失败时丢失暂停标记；审核次数检索还会算入配额复燃 | 先核对时段与存活，失败原子恢复旧 halt且保留新暂停；`watch-window` 覆盖失败、边界和两个预算 |
| 通知两车道校验仍不一致 | 超长数字溢出、前导零解释会改变抑制行为；原并行断言可能掩盖单车道失败 | 使用共同整数规范化；`notify-parity` 独立核对每车道的送达/抑制 |
| 证据历史没有保留策略 | 长期积累已验收目录和共享 blob | 默认保留最新 50 份已验收证据；活动、pending、未验收目录和 journal 保留；写快照和清理共享锁；`evidence-retention` 七项，包括清理失败不撤销持久化验收 |
| halt/注册与脚手架发布不完整 | 直接写 halt可能覆盖人工暂停；初始化注册可能覆盖并发添加；运行脚本发布可能露出半写内容 | halt原子创建且保留已有暂停，注册使用共享锁并保留注释，脚手架临时写入后发布；`park-revive`、`watch-window` 与并发注册回归 |
| launchd 安装器调用裸 `bootout/bootstrap` | 命令不存在，daily 副本缺共享依赖，进程存在不能证明加载了正确脚本 | 改为 `launchctl`，原子拷贝全部依赖，迁移 HOME 路径，核对三个实际作业的 program/arguments；假 launchctl 三项；另用真 nohup/假 worker证明不继承 watchdog 锁描述符 |
| 全局日志仍留在旧 Codex 目录 | 多工具用户难找日志，文档中的迁移计划未落地 | 默认统一到 `~/.codingkeeper/`；不冲突时锁内原子迁移，冲突保留两份历史；`log-location` 四项 |

不是通过削弱验收凑绿。旧 park 静态测试要求直接写 halt和整树回滚，已根据上述数据丢失复现改为实际停炉行为与数据保留断言；原预算、人工暂停、gate/review 和事务检查继续保留。

## 夜间产品改进

方向统一称为 **改进燃料**，具体结果称为 **改进工单**；历史 leaf ID 和 `ck leaves` 保持兼容。

内置目录由 10 类扩展到 32 类，包含工程质量、首次使用、无障碍、多设备、空状态、错误恢复、查找、数据导出恢复、集成/API、隐私、地区、反馈、激活、再次使用、转化、价值表达、收费依据、单位成本、交付就绪和产品机会。每轮确认适用性、真实差距、用户收益、已有工作与可判失败的验收，避免重复根因和虚构需求/指标。

队列为空时轮换燃料；两遍无源码变化后在线等待，默认每小时重新扫描。新 ready 工单优先，燃料/合同或 Git 源码元数据变化会提前续燃。`CODEXC_PROMPT_IDS` 可选择顺序和子集；目录上限扩展为 128，保留原来 54 个自定义加 10 个内置的合法配置。

`ck propose TEXT|--file FILE` 把决策写入 review-needed，锁内原子入队，相同文本幂等，不修改人工暂停和验收事务。Agent先完成独立工作，把价格、方向和外部权限等选择留给人。`ck morning [--hours 12] [--json] [--project PATH]` 只读汇总带 receipt 标记的近期验收、待决策、ready 数、暂停原因与读取问题。

目录、用法、存储策略和交接规则见 [FUEL.md](FUEL.md)。
