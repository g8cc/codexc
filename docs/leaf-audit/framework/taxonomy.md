# 质量检查目录：95个稳定ID

本表是候选检查线索，**每个ID均不自动生成工单、测试、修改或提交**。原P0–P5不再绑定ID，优先级见[PRIORITY.md](PRIORITY.md)。实际项目问题可关联多个ID；同一根因只派一个完整工单。没有UI/网络/数据库等能力时逐项记not-applicable；不要凭目录名称或空peers推断，因为移动端、SDK、同仓客户端也可能构成适用边界。

派单准入：[job-contract.md](job-contract.md) 的适用、当前差距、去重、价值、验收五项缺一不可。下列参考不是“一律实施”的要求；旧 `prompts/*.md` 中固定阈值、固定状态码、指定实现/回滚动作与本表冲突时，应按本表与实际任务合同重写，不得直接投喂旧片段。

拿不到必要证据时保留待核查或明确阻塞，不能当作no-gap/covered/not-applicable。浏览器、设备、读屏或IME行为要在合同所需的边界验证；源码字符串、普通文本fill和旧产物不能代替运行证据。具体重要风险可先做有范围、成本和停止条件的验证任务，不为覆盖目录或补测试数量而生成任务。
