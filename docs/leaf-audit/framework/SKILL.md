# quality-leaf

95个目录ID用于发现、归类和追溯问题，不构成95个待办。用户指定一个ID时，先确认它在目标项目的适用性和价值；用户要求审计目录时，产出判断与证据，不自动实施所有条目。“下一条”默认处理一个完整项目问题；明确授权的批次按该范围继续，不受固定一轮限制。

## 定位与读取

从用户上下文、当前工作目录和仓库标识确认目标项目，不因缺少参数或profile就要求重新填写。多个项目无法区分时，只暂停依赖选择的动作。记录适用仓库约定、起点SHA（无Git时用可识别快照）及已有修改。

框架采用用户明确指定的位置；否则检查本文件所在目录及目标项目已配置的框架路径。以真实存在且相互一致的文件为准，不要求复制到目标仓或安装不存在的runner。核心资源是 [job-contract.md](job-contract.md) 和 [taxonomy.md](taxonomy.md)；按需读取 [PRIORITY.md](PRIORITY.md) 做排序、[scheduler.md](scheduler.md) 做队列与重试、[DIMENSIONS.md](DIMENSIONS.md) 辨别重叠、[thresholds.yaml](thresholds.yaml) 解释参考值。

若核心资源缺失，报告实际路径和缺项，继续已有证据支持的只读核查；不要凭记忆宣称完成目录审计或执行未知叶子。profile是可选事实记录，示例见 [project-profile.example.yaml](project-profile.example.yaml)。命令须经仓库验证，空值代表未知，不执行示例或把未知当不适用。

## 选择与实施

按合同核实实际受影响对象、当前差距、去重、收益/成本和有效验收。相同故障与根因用一个稳定问题ID关联多个目录ID。不存在UI不能只看是否有frontend目录；不存在消费者不能只看peers是否为空。

有明确差距且前置满足的工单才进入ready。若一个具体重要风险尚缺证据，可先建立有范围、成本和停止条件的验证任务，产出该风险的判断；缺测试或数字本身不能自动生成instrument任务。covered、no-gap、not-applicable、duplicate均需留下理由和复查触发条件。队列没有值得执行的工作就停止。

实施遵循 [job-contract.md](job-contract.md)：完成一个完整结果所必需的实现、调用方、验证和文档可以一起改。行为失败本身是基线；性能另需受支持环境、真实负载与项目预算。参考阈值不自动变成验收门槛。

已有修改不自动阻塞；先确认归属与冲突，必要时隔离验证。实验失败不使用整文件checkout/restore或重置工作区清理，只撤可证明属于本轮的补丁，并保留未解决问题、失败证据和有价值的工作。重复失败后暂停相同策略，保留原ID与严重性，记录新假设或解除阻塞的动作，不因次数到限就skip。

## 验证与报告

证据绑定实际SHA或归属diff，并区分已有失败、新回归和环境缺失。浏览器、原生设备、读屏、IME或真实消费者行为，要在合同要求的边界上验证；源码字符串、服务端通过、普通文本fill和旧产物不能替代这些证据。必需检查被SKIP、审查无输出或进程失败，都不能记verified。

报告问题ID与关联目录ID、用户结果、改动范围、实际验证和限制。实现已完成但缺必需证据记implemented/review-needed；全部必需验收满足才记verified。无改动结论、blocked和deferred按 [scheduler.md](scheduler.md) 保留原因与下一动作，不写成修复成功。

本skill不连接模型、不消费服务额度，也不从测试绿推导commit、push、部署或发消息的权限；相关动作遵循用户既有授权和项目规范，已获授权的不重复询问。历史 `prompts/*.md` 仅可作假设线索，使用前按当前合同与taxonomy改写；其中固定顺序、自动提交/回滚等旧规则不生效。
