## 队列和审查机制会扭曲质量判断

1. **阶段门禁与任务数量耦合。** `gate.sh:6–8` 数全文件 `[x]`，并不识别里程碑 ID。移走已完成或把新草案全部写成待办都会降低阶段。先固定 phase1–4 与现有 functional/perf/quality/v2 全量集合，再迁移状态。普通 gate 应强制真实 AI 关闭；当前 `gate.sh:20` 继承环境，`RUN_REAL_AI=1` 会打开 `generate-real.test.mjs:25,324`，不能把默认 skip 当时窗强制措施。
2. **审查只看最近 3 个提交会遗漏本叶。** `review-leaf.sh:20–21,34` 以任务关键词选择 gate 或 `git log -3 -p`，没有固定 base/head。M2b 后有多次修复提交，3 个提交不足以覆盖叶子的原始实现；工作树零改动也不等于目标已完成。应该审本叶记录的 base→head，并对用户原有脏文件做摘要隔离，而不是回滚它们。
3. **审查故障被包装成成功退出。** codex 分支执行后固定 `exit 0`（`:24–25`）；zcode 分支 `wait` 状态仅作为文本进入 Python（`:38–64`），最后 `rm` 成功通常使脚本退出 0。失败/无响应/非法 BUGS 应显式非零且进入 review-needed，不能让上层只靠文字猜。
4. **只读审查不一致。** codex 有 `-s read-only`（`:24`），zcode 用 `--mode yolo --cwd "$PWD"`（`:36`），仅提示“审查”没有同等只读边界。wrapper 本身也不检查 23:00–09:00 UTC+8。无证据说明当前 runner 曾越窗；但直调 wrapper 的路径没有自我保护，本次没有调用它。
5. **“新测试允许”与“tests 被改动即失败”需澄清。** AGENTS 允许新增 `tests/quality` 和 `tests/v2`，review 提示却笼统写 `tests/ 被改动 → BUGS`。应区分修改既有契约、合法新增回归、控制器批准的契约更新，防止实现者为迎合提示重复制造文件。
6. **完成记录不能只留 accepted。** journal 全是轮数/重试数，没有 HEAD、测试命令、pass/fail/skip、基线结果、浏览器证据和真实 AI 标志。M2c 的提交正文有 fake 浏览器自述而队列/journal 未闭环；当前应先核对状态，不能把“未勾选”解释成“没有代码”。

## v2 真实价值与必须讲清的边界

录制、回放、自评的价值是让员工听见并比较自己的表达；这需要真实 Blob、可恢复的 take、可解释的指标，而不是增加测试文件数量。最终验收应从新用户按 README 启动开始，到创建稿→提词→录 10 秒→回放→自评→刷新仍在结束。

另有两处具体契约矛盾需要控制器在真实模型验收前处理：

- SPEC `:36–37,69`、AGENTS 写“服务不落盘任何用户数据”，但 `server.js:401–442` 将 CLI 输出/错误写临时文件再删除，至少生成输出确实落过临时盘。应明确允许的临时输出、清理与失败口径，或调整实现；不能仍宣称“从未落盘”。题目和知识被送进 zcode 的生成请求，也必须与“禁止上传任何用户数据”的范围一致说明，不能将录音不上传扩成生成请求永不离机的承诺。
- `server.js:328–350` 注释称 cwd 是“空目录/不给模型仓库文件面”，实际 `--cwd os.tmpdir()` 是共享临时目录，默认 yolo，仅禁止三个交互工具。cwd 不是文件访问沙箱。本次不认定发生过越权读写，但真实接入验收应证明“只生成文本”使用所需的最小能力，不能复用全能 worker 权限后把这一点当已验证。

建议草案在 [sale.queue.md](sale.queue.md)。它保留归档理由与待验收项，**没有新增任何 done 标记，也没有安装到运行中项目**。
