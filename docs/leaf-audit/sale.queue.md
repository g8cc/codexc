- [ ] M3A 录制生命周期 — 目的：用户能开始、暂停、继续、结束和重新录制，失败后能重试且不遗留资源。范围：新增 recorder 纯状态机与注入副作用接口、相关新测试；先写清 idle/armed/recording/paused/stopped 的合法事件表，包含取消/重置和启动失败回退，不接真实设备。验收：每个合法/非法事件组合有可观察状态与副作用次数断言；重复 stop 不重复保存，重录产生新会话，失败释放已申请资源一次；全量既有回归通过。依赖：无；不得把提词 state.run 冒充 recorder。
- [ ] M3B-MEDIA 录制媒体薄壳 — 目的：摄像头预览叠在提词器上，录制操作真正控制 MediaRecorder。范围：录制适配层、practice 控件/叠层、必要样式和本叶新测试；不做 take 列表或复盘。验收：注入媒体 fake 验证权限拒绝/无设备/不支持 MIME/开始失败的可见提示与重试；暂停续录受 M3A 控制；stop/退出练习释放全部 tracks 与监听器；Blob 在最终 dataavailable 完成后才交出；非 localhost 不调用设备 API。浏览器真实 10 秒录制由 M4-ACCEPT 验收。依赖：M3A。
- [ ] M3B-TAKES 录像持久化与管理 — 目的：录完可找回、删除和导出自己的录像。范围：take repository/现有 storage 接口消费、列表/删除/导出 UI 与新回归；沿用 M1c 驱动，不重写存储抽象。验收：fake recorder 产生含可校验字节的 Blob，保存后读取字节/元数据一致；同次结束不重复保存；写失败明确提示且保留可重试数据；删除目标后其他条目不变；导出文件名/扩展名与 MIME 一致、对象 URL 及时释放；真实 IDB 刷新保真留 M4-ACCEPT。依赖：M3B-MEDIA。
- [ ] M3B-LIMITS 录像时长与存储边界 — 目的：按 SPEC 默认 30 分钟上限与 80% 占用提醒保护本地录像。范围：计时/容量策略纯逻辑、persist/estimate 薄壳和提示；不加上传或自动删除。验收：注入时钟验证 1799/1800 秒界限与暂停口径，达到上限正常收尾且仅保存一次；占用低于/达到 80% 提示符合规则；persist 拒绝或 estimate 不支持时录制仍按定义降级；QuotaExceededError 可见并可导出/清理重试，不虚报保存成功。依赖：M3B-TAKES；先明确有效录制时长是否排除暂停，并与录像时长统一。
- [ ] M4A-METRICS 复盘指标契约 — 目的：指标解释真实且可比较。范围：纯函数 metrics/history、自评 schema 增补和新测试，不做完整复盘 UI。验收：固定 take/draft 得到确定 durationSec/chars/wpm；说明 chars 是稿面字数、wpm 是稿面/时长估算，不冒称转写语速；coveragePct 由用户自评输入，缺值为未填写、有效范围 0–100；0 时长/空稿/缺稿/无效自评不产 NaN 或虚构覆盖率；历史按同一 draft/明确范围排序，空历史和同时间戳稳定。依赖：M3B-TAKES 的 take schema；控制器先补齐 SPEC selfReview coverage 字段，避免 worker 擅改契约。
