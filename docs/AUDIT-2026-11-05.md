# codexc 深度审计与加固 · 2026-11-05

后续发现的 ZCode 套餐时段与旧后台实例问题，见 [ZCODE-WINDOW-2026-11-05.md](ZCODE-WINDOW-2026-11-05.md)。以下为此前启动审计的结果与验证范围。

目标：修复项目启动失败，并沿入口 → tmux → watcher → worker → gate/review → 队列/台账 → 桌面状态的完整链路审计。保留工作区原有的并行审查修改，在独立副本完成复现和测试。

## 启动问题与证据

检查到既有 `codexc-entry-test` 空白窗格只有 Bash 包装进程；采样显示它阻塞在 `read`，没有进入 Codex。采样本身不能唯一确定旧实例的源码路径；历史代码已有通过命令替换启动后台 watcher 的阻塞记录，继承的管道会让父 shell 等不到 EOF。现改为短生命周期 Python launcher，在启动 watcher 前明确重定向所有标准流、关闭额外描述符并脱离终端。启动回归必须确认假 worker 实际执行，不能仅检查 watcher.pid。另在独立 HOME、私有 tmux 和有终端握手的 PTY 中验证了本机 Codex 0.162.1：原生 CLI、codexc --no-daemon 和默认 codexc 均显示输入界面；未提交模型任务。可用 `python3 tests/native-startup-smoke.py` 复跑该可选冒烟（不纳入默认离线套件）。

当前源码还复现了以下独立的启动失败：

- `TMPDIR` 未设置时，`set -u` 令 watcher 初始化提前退出。
- 只缺部分 retry 参数时，自修复会写入重复 TOML 键。
- 已有单引号项目表未按 TOML 语义识别，预信任可能重复声明。
- 无效工具参数未二次校验，悄悄启动 Codex；`codexc codex ...` 则把多余子命令传给 Codex。
- `loop --no-loop` 仍启动循环；自动会话识别会接入同目录的普通 shell 或失效包装进程。
- 新客户端的通知、数据目录、审查配置被旧 tmux server 环境覆盖。
- tmux 重启后残留的 TMUX/TMUX_PANE 让入口误认为仍在有效窗格内；现在验证精确 pane，失效时按外部终端重新建会话。

新配置编辑器使用独占文件锁、随机临时文件、保留原权限（新文件 0600）、原子替换和发布前解析；保留未知设置、已配置 retry 值和显式信任选择。有效的 inline `projects = {}` 无法追加新表时保留原配置并提示跳过自动预信任。损坏的 Claude JSON 不再被清空重建。

## 性能改动与边界

- `ck status` 从每项目多个 shell/外部命令，改为一个 Python 进程聚合；注册表按物理路径去重。
- TUI 完成判断用本轮字节水位，只解析有限尾部（约 400 行、最多 4 MiB），取消每轮全日志计数。
- Codex watcher 的进程树使用去重的逐层遍历，`lsof` 从每 PID 一次改为合并查询；未发现 rollout 时按配置轮询间隔等待。
- 桌面状态最多每两秒在后台扫描一次；hover 复用快照、图标缓存，清理过期事件去重记录。
- 保留原工作区的并行 review 意图，每批独立审查仍计入总次数预算，只有全部成功且零 bug 才通过。

本机 100 项目离线 `ck status` 聚合基准：每项目相同队列/状态/台账，预热后交错测量三次，旧版中位 **11.3744s**，新版 **0.1601s**（约 71.1 倍）。两版均输出相同项目数及队列计数，fixture 未改变。该结果仅适用于这个聚合基准，不代表所有真实启动场景。原始采样和源码哈希：[status-benchmark-2026-11-05.json](status-benchmark-2026-11-05.json)，复现脚本：`tests/benchmark-status.py`。

## 运行与兼容说明

- 配置安全编辑需要 Python 3.11+ 的 `tomllib`；其它依赖仍为 macOS、tmux 3.5+、sqlite3、相应工具 CLI。
- 现有活跃 watcher 复用，不再每次 attach 杀死重建；新实现随新会话/缺失 watcher 启动生效。无 owner 元数据的旧会话可以接入，需重新启动会话后启用新 watcher/定时发送。
- 项目状态目录需要可写；损坏配置或锁元数据会报错并停止自动操作。
- 自动审批模式仍遵循现有 `CODEXC_AUTO_YES=0/1/2` 约定；用户显式审批/沙箱参数（包括紧凑短参数）优先。
- 桌面源码已验证编译及数据/事件边界，已安装的桌面二进制未替换；实际视觉、多屏交互、真实模型服务与各 CLI 升级兼容性不属于离线套件的验证范围。
- dsh 的新会话发现仍依赖项目会话目录时间排序，独立 CLI 在同项目并发创建会话时可能存在归属歧义；本轮未通过真实服务验证该行为。
